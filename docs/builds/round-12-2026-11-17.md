## What this round delivered (the owner's decree, 2026-11-17)

1. **THE FIREFOX PROTOCOL IS RETIRED, END TO END.** The owner: «پروتکل فایرفاکس رو به صورت کلی از اپ حذف کن چون مشکلات زیادی داره هم از بک اند و هم از ui برنامه.» The engine child (`phase1/` — the Go `libfirefoxvpn`, the dnsresolver package, the WebChannel login, the discovery and usage roles), the Kotlin bridge (the Keystore vault crypto, the PID ownership trio, the WebView proxy override), the Dart surface (the login/discovery/session/quota models, the engine-adapter chain, the store state), the UI (the protocol page's Firefox card, the settings Firefox pill, the login screen), the l10n entries (5 locales) and the CI `firefox-engine` job are all gone. The APK gate asserts the engine's ABSENCE — a regression cannot slip back in silently.
2. **The scan-speed section is BACK on the protocol page** («کارت سرعت اسکن رو به صفحه انتخاب پروکل برگردون و جایگزین کارت فایرفاکس کن») — the pre-PHASE-2 geometry restored verbatim (heading top 736, pills top 776, the device-frame content column), replacing the retired Firefox card. Connection Settings loses the section (the protocol-page suite covers the interaction).
3. **The «آدرس هسته ها» server pills are BACK on the settings main page** («مثل ضاهر قبلش») — the pre-v1.5.0 look restored; each pill now opens its core's own GitHub repository. The general-settings move is retired.
4. **The WireGuard reconnect loop is FIXED in the Aether core** (the attached log's own evidence): the tunnel validated end-to-end, then `the exit location could not be read, so the policy cannot be honoured` tore it down every ~10 s. `exitloc::settle` now retries the trace read 3× (2 s pause) and — when the trace stays unreadable — **serves the already-validated tunnel unverified** while the periodic policy guard keeps watching (it reconnects the moment it can READ a violating location, and tolerates unreadable checks). The `--exit-loc` policy still rejects a READABLE wrong location immediately. Verified: the module compiles clean and its 10 unit tests pass under the pinned Rust 1.99.1.
5. **The app's custom DNS is GONE** (round 11's decree, completed app-side): the `--dns` flag, the CoreSettings field and the core-page row are retired — the core's own built-in resolver (1.1.1.1 / 1.0.0.1) serves every tunnel. A user-selected resolver could never answer from inside the WARP tunnel and poisoned the exit-location check (the same root as defect 4).
6. **The home widget deck** («برای صفحه اصلی چندتا ویجت خلاقانه اضافه کن»): three live cards under the hero band — the ticking session timer (Watch 1), the ping sparkline ECG (Activity 4, a CustomPainter over the last 40 samples) and the session data card with the down/up split bar (Download). Every glyph from the app's own icon set; every value honest (idle placeholders, never a guess).
7. **The control-center surfaces** («برای بخش کنترل سنتر گوشی هم ویجت اضافه کن … از آیکون و فایل های خود اپ استفاده کن»):
   * the **Quick Settings tile** — the brand A-mark (`ic_stat_aethone`), the honest service state; tap on a LIVE tunnel runs the service's own `ACTION_DISCONNECT` (native, no UI); tap while idle launches the app with the quick-connect flag;
   * the **home screen widget** — the 2×1 connection card (the app's card grammar, the brand mark, the Off-glyph power button); the body opens the app, the power slot toggles like the tile; the VPN service pushes its state on start/stop (never a stale reading);
   * the **quick-connect hand-off** — `EXTRA_QUICK_CONNECT` → `onNewIntent`/`takeQuickConnect` → the store's own `connect()` (no second engine channel).
