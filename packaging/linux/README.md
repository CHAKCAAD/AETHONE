# AETHONE روی لینوکس — راهنمای نصب نسخه ۱.۰.۱

نسخه ۱.۰.۱ برای لینوکس با **پنج قالب** از همان سورس و همان هسته‌هایی که نسخه اندروید r97 از آن‌ها ساخته شده منتشر می‌شود؛ همه در کف x86-64-v1 و با glibc 2.39 ساخته شده‌اند و روی پردازنده‌های قدیمی (از Ivy Bridge به بعد) هم اجرا می‌شوند.

| قالب | فایل | مناسب برای |
| --- | --- | --- |
| پرتابل | `aethone-linux-x86_64-1.0.1.tar.gz` | هر توزیعی؛ بدون نصب |
| دبیان | `aethone_1.0.1_amd64.deb` | Debian 13+، Ubuntu 24.04+، Mint 22+، Pop!_OS 24.04+ |
| ردهت | `aethone-1.0.1-1.x86_64.rpm` | Fedora 40+، openSUSE Tumbleweed / Leap 16 |
| اپ‌ایمیج | `AETHONE-1.0.1-x86_64.AppImage` | هر توزیع x86_64 — تک‌فایل، قابل اجرا |
| فلت‌پک | `aethone-1.0.1-x86_64.flatpak` | هر توزیعی که فلت‌پک دارد (ران‌تایم GNOME 48) |

جدول SHA256 همه فایل‌ها در `SHA256SUMS-linux-*.txt` همان ریلیز است؛ قبل از نصب بررسی کنید:

```bash
sha256sum -c SHA256SUMS-linux-*.txt --ignore-missing
```

## ۱) نصب بر اساس توزیع

### دبیان / اوبونتو / مینت و مشتدها

```bash
sudo apt install ./aethone_1.0.1_amd64.deb
```

برنامه در منوی برنامه‌ها با نام AETHONE ظاهر می‌شود و دستور `aethone` هم در PATH است. وابستگی‌ها: GTK3 (نصب خودکار)؛ برای حالت تونل، `policykit-1` توصیه می‌شود (روی دسکتاپ‌ها به‌طور پیش‌فرض هست).

> کف پشتیبانی: Debian 13+ / Ubuntu 24.04+ (به‌خاطر glibc 2.39). روی Debian 12 از AppImage یا Flatpak استفاده کنید.

### فدورا / اوپن‌سوزه و مشتدها

```bash
sudo dnf install ./aethone-1.0.1-1.x86_64.rpm     # فدورا
sudo zypper install ./aethone-1.0.1-1.x86_64.rpm  # اوپن‌سوزه
```

### Arch و مشتدها

نسخه پرتابل یا AppImage را استفاده کنید؛ دستورالعمل `packaging/linux/aur/PKGBUILD` در مخزن برای بسته‌بند AUR آماده است.

### فلت‌پک (هر توزیع)

```bash
flatpak install ./aethone-1.0.1-x86_64.flatpak
flatpak run com.chakcaad.Aethone
```

اگر ران‌تایم GNOME 48 ندارید، فلت‌پک خودش آن را از Flathub می‌گیرد.

### AppImage (هر توزیع)

```bash
chmod +x AETHONE-1.0.1-x86_64.AppImage
./AETHONE-1.0.1-x86_64.AppImage
```

### پرتابل (بدون نصب)

```bash
tar xzf aethone-linux-x86_64-1.0.1.tar.gz
./aethone-linux-x86_64/aethone
```

## ۲) حالت تونل (VPN) — دسترسی مدیر و helper

حالت تونل کل دستگاه را از روی TUN عبور می‌دهد و به `CAP_NET_ADMIN` نیاز دارد. برای این کار یک helper کوچک (`aethone-tunnel-helper`) همراه با اکشن Polkit نصب می‌شود:

- **deb / rpm / AppImage / پرتابل**: در اولین اتصال تونل، **یک بار** رمز مدیر پرسیده می‌شود تا helper در مسیر سیستم (`/usr/libexec`) نصب شود؛ اتصال‌های بعدی همان پرومپت معمولی اتصال را می‌گیرند. در قالب‌های deb و rpm این فایل‌ها از قبل نصب شده‌اند، پس حتی همان یک بار هم پرومپت نصب نمی‌بینید.
- **فلت‌پک**: سندباکس نمی‌تواند helper را روی سیستم میزبان نصب کند؛ بسته همراه `aethone-tunnel-helper_1.0.1_amd64.deb` (یا rpm) **یک بار روی میزبان** نصب کنید:

  ```bash
  sudo apt install ./aethone-tunnel-helper_1.0.1_amd64.deb
  # یا روی فدورا/اوپن‌سوزه:
  sudo dnf install ./aethone-tunnel-helper-1.0.1-1.x86_64.rpm
  ```

  پس از آن، حالت تونل داخل فلت‌پک با پرومپت معمولی pkexec میزبان کار می‌کند (پل `flatpak-spawn --host`). حالت پروکسی به این بسته نیازی ندارد.

## ۳) پروکسی سیستم هنگام تونل (درخواست مالک)

وقتی حالت تونل فعال است، علاوه بر تونل‌شدن کل ترافیک، **پروکسی سیستم هم به سوکاس‌۵ محلی همان تونل** (`socks5://127.0.0.1:<port>`) ست می‌شود تا مرورگرها و برنامه‌های پروکسی‌محور هم از اتصال استفاده کنند؛ با قطع اتصال، وضعیت قبلی سیستم **بازگردانی** می‌شود (و اگر برنامه وسط کار بسته شود، در اجرای بعدی به‌صورت بهداشتی بازگردانی می‌شود).

پشتیبانی دسکتاپ‌ها در نسخه ۱.۰.۱:

| دسکتاپ | سازوکار | وضعیت |
| --- | --- | --- |
| GNOME / Ubuntu / Fedora Workstation / Pop!_OS / Cinnamon / MATE / Budgie | `gsettings` (org.gnome.system.proxy) | کامل |
| KDE Plasma 5 / 6 | `kwriteconfig6/5` روی `kioslaverc` (همان کلیدهایی که Firefox و Chromium زیر پلاسما می‌خوانند) | کامل |
| XFCE و بقیه | اسکیمای gsettings در صورت نصب بودن (فایرفاکس همان را می‌خواند) | در حد موجودی اسکیما؛ در غیر این صورت تونل کار می‌کند و فقط پروکسی سیستم ست نمی‌شود و خطای صادقانه در لاگ ثبت می‌شود |

داخل فلت‌پک هم همین رفتار برقرار است: نوشتن‌های gsettings از طریق مجوزهای dconf به تنظیمات میزبان می‌رسند و ابزارهای KDE از طریق `flatpak-spawn --host` روی میزبان اجرا می‌شوند.

## ۴) نکته‌ها

- **سازگاری CPU/سیستم**: کد در کف x86-64-v1 کامپایل شده (بدون نیاز به AVX2 و…) و سقف گلیبسیک 2.39 است؛ گیت CI روی همه ELFهای بسته درِ ISA را fail-closed نگه می‌دارد.
- **آیکون و منو**: در همه قالب‌ها، فایل `.desktop` و آیکون hicolor (۱۶ تا ۲۵۶) نصب می‌شوند.
- **حالت پروکسی** (بدون TUN) در همه قالب‌ها و بدون هیچ دسترسی مدیر کار می‌کند.
- **اپدیت**: نصب نسخه‌های بعدی روی همین نسخه، در deb/rpm/flatpak مستقیم انجام می‌شود؛ AppImage و پرتابل فقط جایگزین‌شدن فایل‌اند.

## ۵) ساخت از سورس

اسکریپت `packaging/linux/build_packages.sh` از خروجی `flutter build linux` (به همراه هسته‌های staged) هر پنج قالب را می‌سازد و اعتبارسنجی fail-closed انجام می‌دهد؛ کانونیکال‌ترین اجرای آن job بسته‌بندی در `.github/workflows/native-ci.yml` است (همان pins، همان درِهای ISA).
