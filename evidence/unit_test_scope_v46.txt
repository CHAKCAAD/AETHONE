1.2 Offline-safety analysis (why these can run in CI without tunnels):

    * NO external URL appears anywhere in src/ (machine grep for
      https?:// outside comments: zero hits).
    * Network-touching test code uses LOOPBACK binds (127.0.0.1:0,
      [::1]:0) plus in-process relays/shims; representative pattern
      (socks.rs): bind_listener("test", "127.0.0.1:0".parse().unwrap())
      followed by TcpStream::connect(dialled) on the same process.
    * reqwest appearances inside test modules are TYPE-LEVEL only
      (StatusCode/HeaderMap construction and assertions — account.rs,
      upstream.rs, zerotrust.rs); no .send() to any external host.
    * upstream.rs "detour" tests reference external-IP literals
      (162.159.192.1:2408, [2606:4700:d0::a29f:c001]:2408) as TOKEN
      peers that the in-process shim rewrites to a local relay; the
      assertions expect the relay's echo ("pong:ping"), which only the
      local relay produces.
    * tor.rs tests (7) exercise bridge/parameter parsing without any
      connection; the tor feature's Arti stack is COMPILED (that is the
      coverage the job adds) but no Tor network contact is attempted.

1.3 boring-sys 5.3.0 patch (host parity):

    The build legs patch the registry source
    (CARGO_HOME/registry/src/*/boring-sys-5.3.0/build/main.rs) because
    Bindgen 0.72 emits "pub const ERR_LIB_SSL : _bindgen_ty_2 = ..."
    and the upstream helper searched the literal "ERR_LIB_SSL:" — the
    same generation runs on the HOST target, so cargo-test applies a
    BYTE-IDENTICAL copy of the build_native.sh step (verified by diff
    during validation; build_native.sh itself untouched). The python
    guard refuses to patch unless Cargo.lock pins boring-sys exactly
    5.3.0 and exactly one build/main.rs exists.
